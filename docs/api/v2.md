# Client API v2

Use v2 for new clients. Read [authentication, errors and limits](README.md) first.
Examples assume `BASE=http://localhost:5274`, `ALLSTARR_TOKEN` and IDs copied from
actual responses. The [OpenAPI file](../../apis/specifications/allstarr/client-v2.json)
contains the full JSON schemas. JSON names below use their wire spelling.

## IDs and track shape

Track reads accept any supported ID spelling: the returned v2 `trk_` ID, a native
library item ID, or an older `ext-` song ID. These are aliases, not separate songs.
Two spellings of one recording return one track with both in `aliases`.
Keep the returned `id`; do not construct or decode it. A recording-backed ID
survives keeping, adding to the library and rematching. A later merge can rename
it; follow `track.renamed` events and refresh stored references.

Every `V2Track` has the same shape:

| Fields | Meaning |
| --- | --- |
| `id`, `aliases` | Stable track ID and other accepted spellings. |
| `canonicalRecordingId` | Recording identity shared by library and service copies, or null. |
| `isExternal`, `libraryItemId`, `provider`, `externalIds` | Library identity and known service/recording identifiers. Provider has `id`, `name`, `iconUrl`, `glyphUrl`. |
| `title`, `artists`, `albumArtists`, `featuring`, `album` | Names and references. Artist references have `id`, `name`; album has `id`, `name`, `title`. Reference IDs can be null. A reference to something in the media server library also has `libraryId`, the media server's own id for it; an artist or album only on a service has `aliases` with its older `ext-` id instead, which the media-server routes accept, and `provider` `{id,name,iconUrl,glyphUrl}` naming the service. On a song from a service, an artist whose name matches one artist in the listener's library points at that library artist (it has `libraryId`), unless the listener marked the service artist as someone else. |
| `disc`, `track`, `durationMs`, `year`, `explicit` | Recording metadata; unknown values can be null. |
| `artwork` | `{url}`; append `?w=<pixels>` to request a width, clamped to 32–2,048 (default 600). The URL changes with the image. A song or album whose service gives no cover answers 404, never a stand-in: draw your own placeholder. On the Jellyfin-shape image route (`/Items/{id}/Images/Primary`) add `standin=0` for the same answer; without it that route sends the service's mark. A lookup that runs out of time answers `503` with `Retry-After` instead: ask again, the cover may exist. |
| `format` | Stored or measured source facts: `container`, `codec`, `bitrate` in bits/s, `sampleRate` in Hz, `bitDepth`, `channels`, `isLossless`. This does not describe converted playback. |
| `trackGainDb`, `albumGainDb` | ReplayGain values at the −18 LUFS reference, or null. A service song's file is measured once when a complete copy is cached, so `trackGainDb` can arrive during its first play (see `track.updated` with `changed`). |
| `saved`, `playCount`, `lastPlayedAt` | This listener's saved and listening state. |
| `keep`, `match`, `lyrics` | `{state,progress}`, optional `{state,confidence,authority}`, and `{available,format,source}`. Lyrics text requires a view. |

## Optional data and validators

`include` adds related resources. `views` adds computed data about a resource.
Names are comma-separated and case-sensitive. Unknown names, duplicate names and
empty list entries return `400`; an omitted or empty value asks for none.

The single-track views are `lyrics`, `lyricsSources`, `match` and `autoplay`.
Track lists support only `lyrics`. Track includes support only `album`.
Album options are separate and described below.

Conditional reads return an `ETag`. Store it with that exact representation,
including its include/view options. Send `If-None-Match` to receive `304` without
a body when it still matches. Responses use `Cache-Control: no-store`; retain
only the private application state your client needs. Conditional reads can
still perform work before comparing the representation.

## Session

### `GET /allstarr/v2/session`

Read `{listener:{id,name},serverVersion,build?,features,dashboard?,library,libraryAdditions}`. No parameters. `library` is the media server's own mark `{id,name,iconUrl,glyphUrl}`, shown on library results beside the services'. `libraryAdditions` is `{canAddDirectly,requiresApproval,defaultUnit,setupNeeded?}`: whether this listener's adds start at once or wait for approval, and whether an add button adds the `song` or the `album`. `setupNeeded` is present while every add would be refused, with the sentence to show (for example that a naming pattern must be confirmed in library settings); offer no add button then. `build` (such as `git-8e707c79`) changes with every release, unlike `serverVersion`; it is absent in development builds.
`features` has boolean keys `tracks`, `albums`, `artists`, `batch`, `playback`, `events`,
`artistLinks`, `lyricsTranslation`, `autoplay`, `trackFacts`, `lyricsSources`,
`trackMatch`, `appearances`, `similarAlbums`, `playbackStatus`, `mixes`, `releases`,
`libraryAdditions`, `artistFollow`, `reports`, `karaokeModel`, `providerIcons`,
`history`, `historyImports`, `historyRecheck`, `stats`, `sound`, `taste`,
`preferences`, `myLibraries`, `search`, `lyricsSearch`, `lyricsSearchServices`,
`lyricsSearchServicesResolve`, `playbackRequestStatus`, `tracksFacts`, `mixRows`, `historyRows`, `trackLyrics`,
`artistCandidates`, `artistIdentity`, `albumIdentity`, `trackLoudness`, `resumableDownloads`, `librarySize` and `additionSteps`.
Both `trackFacts` and `tracksFacts` are sent; `tracksFacts` announces
`/tracks/facts`. `lyricsTranslation` follows the translation setting. `dashboard`, when configured, is `{url}` with the same
public dashboard address as v1 capabilities. Optional header `If-None-Match`.
This read is also available in a batch.

```bash
curl -H "Authorization: Bearer $ALLSTARR_TOKEN" "$BASE/allstarr/v2/session"
```

## Track resources

### `GET /allstarr/v2/tracks`

Read several tracks in requested order. Required query `ids` is a comma-separated
list of 1–100 nonempty IDs. Optional `include=album` adds `albums`, a map keyed by
album ID. Optional `views=lyrics` adds `views` and `viewStatus` maps keyed by the
returned track ID. `If-None-Match` is optional.

Returns `{tracks:[V2Track],missing:[id],albums?,views?,viewStatus?}`. Unknown or
hidden IDs are in `missing`; aliases collapse to one track. Reading tracks
never opens their audio.
A service song the listener has in the library reads as the library copy
(`libraryItemId` set, the service id among `aliases`), including one never
played or saved, when its ISRC names a library song.
IDs that cannot be a song, such as an album's or a malformed one, are also in `missing`.
Stored metadata and listener facts are read in batches, including for 100 IDs;
`provider` describes the metadata source, without predicting a playback route.

```bash
curl -G -H "Authorization: Bearer $ALLSTARR_TOKEN" \
  --data-urlencode "ids=$TRACK_ID,$OTHER_TRACK_ID" \
  --data-urlencode 'include=album' --data-urlencode 'views=lyrics' \
  "$BASE/allstarr/v2/tracks"
```

### `GET /allstarr/v2/tracks/facts`

Read only the listener facts of up to 100 tracks (session feature
`tracksFacts`), for lists whose rows already show title, artists and artwork.
Required `ids` takes the same spellings as `/tracks`. Returns
`{tracks,missing}`; each entry is `{id,aliases,isExternal,libraryItemId,
canonicalRecordingId,provider,externalIds,format,explicit,saved,playCount,
lastPlayedAt,keep,match,lyrics,trackGainDb,albumGainDb}` with the same meanings as on `V2Track`; the gains are a service
song's measured values (library songs carry their media server's own). It
reads no media-server metadata, so it costs about what the facts cost to read.
Ids that are unknown, hidden or cannot be songs are in `missing`. Available in
a batch.

### `GET /allstarr/v2/tracks/{id}`

Read one track by any accepted spelling. Optional query `include=album`,
`views=lyrics,lyricsSources,match,autoplay` and header `If-None-Match`.
Choose only the views you need. Unknown or hidden tracks return `404`.

Returns `{track:V2Track,albums?,views?,viewStatus?}`. View fields with no data are
omitted. `viewStatus` reports each requested view as `ok`, `none`, `unavailable`
or, for autoplay, `partial`. A failed view does not discard the track.

| View | Shape |
| --- | --- |
| `lyrics` | `{source,format,lines:[{startMs,endMs,text,part,words:[{startMs,endMs,text}],voice?,singer?}]}`. Unknown line timing and word end times remain null. |
| `lyricsSources` | `{sources,chosen,revision}` using `ClientLyricsSources` from the schema. |
| `match` | `{state,confidence,authority,current,candidates,revision}` using `ClientItemMatch`. |
| `autoplay` | `{tracks:[V2Track],next}` with up to 25 tracks initially. Follow its continuation resource. |

This read never opens audio, even with views. Use playback resolution when the
listener intends to play or prefetch a song.

```bash
curl -H "Authorization: Bearer $ALLSTARR_TOKEN" \
  "$BASE/allstarr/v2/tracks/$TRACK_ID?include=album&views=lyrics,lyricsSources,match,autoplay"
```

### `GET /allstarr/v2/tracks/{id}/lyrics/translation`

Translate the lines from the lyrics view while preserving their order. Optional
query `to` is a BCP-47 language such as `en`, `es` or `pt-BR`, default `en`.
Invalid languages return `400`. Optional header `If-None-Match`.
Disabled translation, a hidden track or absent lyrics returns `404`.

Returns `{trackId,to,provider,lines:[{index,source,text,from}]}`. Each original
line has one entry, including blank lines. `text` is null when no translation
is needed or a result is dropped. `from` can be null. `provider` is `google`,
`mymemory`, `libretranslate` or null. Results are shared for 30 days by track,
lyrics text and target language. Translation does not add timing.

```bash
curl -H "Authorization: Bearer $ALLSTARR_TOKEN" \
  "$BASE/allstarr/v2/tracks/$TRACK_ID/lyrics/translation?to=es"
```

### `GET /allstarr/v2/tracks/{id}/lyrics`

Read the track's lyrics alone (session feature `trackLyrics`): the body is exactly
what `views.lyrics` holds on a track read, without reading the track. Query
`sourceId` reads one version from `lyrics/sources`. A library song named by its
recording reads from the library copy. Returns `404` when there are no lyrics.
Supports batch and ETags.

### `GET /allstarr/v2/tracks/{id}/lyrics/sources`

Read `{sources,chosen,revision}` with the same version, ranking and choice
semantics as the lyrics sources view. Optional `includeLyrics=true` includes
each version's rich lyrics. `chosen` has `{sourceId,layer}`; `revision` has
`personal` and `household` stamps, each null or `{id,revision}`. Optional header
`If-None-Match`. Hidden or unknown tracks return `404`; malformed IDs return
`400`. This read is also available in a batch.

```bash
curl -H "Authorization: Bearer $ALLSTARR_TOKEN" \
  "$BASE/allstarr/v2/tracks/$TRACK_ID/lyrics/sources?includeLyrics=true"
```

### `PUT /allstarr/v2/tracks/{id}/lyrics/source`

Choose a version for this listener with `{sourceId,expectedRevision}`. Copy the
revision object from the sources read. Returns `{chosen,revision}`. A stale
revision or unavailable version returns `409`; missing fields return `400`.

```bash
curl -X PUT -H "Authorization: Bearer $ALLSTARR_TOKEN" -H 'Content-Type: application/json' \
  --data "{\"sourceId\":\"$SOURCE_ID\",\"expectedRevision\":$LYRICS_REVISION}" \
  "$BASE/allstarr/v2/tracks/$TRACK_ID/lyrics/source"
```

### `DELETE /allstarr/v2/tracks/{id}/lyrics/source`

Clear this listener's choice and restore the household choice or automatic
selection. Body: `{expectedRevision}`, using the latest sources or selection
response. Returns `{chosen,revision}`. Stale revisions return `409`.

```bash
curl -X DELETE -H "Authorization: Bearer $ALLSTARR_TOKEN" -H 'Content-Type: application/json' \
  --data "{\"expectedRevision\":$LYRICS_REVISION}" \
  "$BASE/allstarr/v2/tracks/$TRACK_ID/lyrics/source"
```

### `GET /allstarr/v2/tracks/{id}/match`

Read `{state,confidence,authority,current,candidates,revision}`. Candidates carry
opaque `candidateId` handles, recording metadata, provider, confidence and
reasons. No parameters. Optional header `If-None-Match`. Tracks without a visible
match return `404`; malformed track IDs return `400`. Available in a batch.

```bash
curl -H "Authorization: Bearer $ALLSTARR_TOKEN" \
  "$BASE/allstarr/v2/tracks/$TRACK_ID/match"
```

### `PUT /allstarr/v2/tracks/{id}/match`

Pin `{candidateId,expectedRevision}` from the match read for this listener.
Returns the updated match. A stale revision returns `409`; an unavailable
candidate returns `400`. Administrator tokens also create personal choices here.

```bash
curl -X PUT -H "Authorization: Bearer $ALLSTARR_TOKEN" -H 'Content-Type: application/json' \
  --data "{\"candidateId\":\"$CANDIDATE_ID\",\"expectedRevision\":\"$MATCH_REVISION\"}" \
  "$BASE/allstarr/v2/tracks/$TRACK_ID/match"
```

### `DELETE /allstarr/v2/tracks/{id}/match`

Clear this listener's override, restoring the household or automatic match.
Required query `expectedRevision` is the opaque revision from the latest match
response. Returns the updated match; stale revisions return `409`.

```bash
curl -X DELETE -G -H "Authorization: Bearer $ALLSTARR_TOKEN" \
  --data-urlencode "expectedRevision=$MATCH_REVISION" \
  "$BASE/allstarr/v2/tracks/$TRACK_ID/match"
```

### `POST /allstarr/v2/tracks/{id}/match/reject`

Reject the effective match for this listener with `{expectedRevision}`. Returns
the updated match, with `state:rejected` and null `current`. Stale revisions
return `409`.

```bash
curl -X POST -H "Authorization: Bearer $ALLSTARR_TOKEN" -H 'Content-Type: application/json' \
  --data "{\"expectedRevision\":\"$MATCH_REVISION\"}" \
  "$BASE/allstarr/v2/tracks/$TRACK_ID/match/reject"
```

### `GET /allstarr/v2/tracks/{id}/appearances`

Read `{trackId,songCount,appearances}` for this listener's mixes and synced
playlists containing the track. Each appearance has
`{kind,id,title,subtitle,coverUrl,matchedSongCount,playlistId,playlistLibraryId?}`. IDs use v2 track,
mix and playlist spellings; `playlistLibraryId` is the media server's id for a
playlist, which `/Playlists` routes take. No parameters. Optional header `If-None-Match`.
Hidden tracks return `404`; malformed IDs return `400`. Available in a batch.

```bash
curl -H "Authorization: Bearer $ALLSTARR_TOKEN" \
  "$BASE/allstarr/v2/tracks/$TRACK_ID/appearances"
```

### `GET /allstarr/v2/tracks/{id}/autoplay`

Continue a queue after a seed track. Optional query `limit` is 1–50, default 25;
`cursor` is the opaque `next` value from the previous page. Optional header
`If-None-Match`. Keep the seed ID unchanged while following pages.

Returns `{tracks:[V2Track],next}`. It tries native InstantMix or service radio,
similar songs, the artist, then the album. Pages avoid repeats within the bounded
continuation history. A partial page can be empty and still have `next`; null
means exhausted. A malformed cursor or a cursor for another seed returns `400`.

```bash
curl -G -H "Authorization: Bearer $ALLSTARR_TOKEN" \
  --data-urlencode "cursor=$CURSOR" --data-urlencode 'limit=25' \
  "$BASE/allstarr/v2/tracks/$TRACK_ID/autoplay"
```

## Album resource

### `GET /allstarr/v2/albums/{id}`

Read a native or service album using its v2 or older album ID. Optional
`include=tracks` adds native v2 track shapes in disc and track order.
Optional `views=more-by-artist` adds up to 20 other albums from the first
identified album artist. Optional header `If-None-Match`.

Returns `{album,tracks?,missing?,views?:{moreByArtist:[album]}}`. Album summaries
have `{id,title,artists,year,isExternal,artwork,libraryId?,aliases?,explicit?}`;
`libraryId` is the media server album when it is in the library and `aliases`
holds a service album's older `ext-` id, which the media-server routes use.
`explicit` is true for
a service's explicit edition, false for its clean one, and absent when unknown.
`missing` lists requested album tracks that could not be returned. Unknown albums
return `404`; unknown option names return `400`.

A service album also says which of the listener's library albums it is (session
feature `albumIdentity`), read from the libraries the listener chose. Albums
are joined only on proof:

- `libraryAlbum` is set when the service album is proven to be a library album
  by its songs: `{id,title,artwork,libraryId,year?,songCount?,by,ownedSongs,ownedTracks}`.
  `by` is `songs` (songs of this album are the listener's own songs on that
  library album, by recording) or `titles` (every song of the shorter of the
  two albums is on the other: the same title and version, and lengths within
  twelve seconds, or the same song artist where a service's album list gives
  no lengths). `ownedSongs` is how many
  songs they share and `songCount` how many the library album has, so a
  listener who has five songs of a fifteen-song album gets `ownedSongs: 5`.
  Open the library album with `libraryId`.
- `couldBe` lists up to five library albums with the same artist and title whose
  songs do not prove them the same (an artist can have two albums of one name),
  or several that do: `[{id,title,artwork,libraryId,year?,songCount?,reason}]`.
  `reason` is a short sentence to show.

`ownedTracks` lists the shared songs as `[{id,libraryItemId}]`: `id` is the
song's id in this album's `tracks`, `libraryItemId` the listener's own song.
A `couldBe` album that shares songs carries `ownedSongs` and `ownedTracks` too.
Both count songs on that one library album; a row can also be the listener's
through its own `libraryItemId`, on another library album.
Album titles and song counts alone never join albums. A row in `tracks` keeps
its own id and carries a `libraryItemId` only when its recording is known to be
the listener's, so a song found by title is marked through `ownedTracks`.

Both are absent for a library album and when the library has no album of that
artist and title. The answer is the same with and without `include=tracks`.

An album a search or an artist page listed is stored without its songs. A read
with `include=tracks` asks the service for the album itself the first time, so
the first read of such an album takes as long as the service does.

```bash
curl -H "Authorization: Bearer $ALLSTARR_TOKEN" \
  "$BASE/allstarr/v2/albums/$ALBUM_ID?include=tracks&views=more-by-artist"
```

### `GET /allstarr/v2/albums/{id}/similar`

Read `{albumId,basedOn,albums}` using the same related-artist picks as v1,
preferring library albums when available. Optional `limit` is 1–24, default 12.
Albums have the usual v2 summary fields plus `songCount`, `source`, `provider`,
and `libraryId` (a library album) or `aliases` (the older `ext-` id of a service
album). Optional header `If-None-Match`. Hidden or unknown albums return
`404`; malformed IDs and invalid limits return `400`. Available in a batch.

```bash
curl -H "Authorization: Bearer $ALLSTARR_TOKEN" \
  "$BASE/allstarr/v2/albums/$ALBUM_ID/similar?limit=12"
```

## Artist resource

### `GET /allstarr/v2/artists/{id}`

Read a library or service artist using its v2 or older artist ID, such as the
`id` on a track's artist reference. Optional `include=albums` adds up to 50 of
the artist's albums, newest first for library artists; a service artist's list
also has the same artist's albums from the listener's other services (an artist
joins only when it shares an album with this one). `include=tracks` adds up
to 20 top songs as native v2 track shapes. Optional header `If-None-Match`.

Returns `{artist,albums?,tracks?,missing?}`. The artist has
`{id,name,isExternal,artwork,genres,following,libraryId?,provider?}`: `following`
says whether this listener follows the artist for new releases, `libraryId` is
the media server's id when the artist is in the library, and `provider`
(`{id,name,iconUrl,glyphUrl}`) names the service of an artist that is not in the
library. Albums use the album summary shape. Unknown artists return `404`; unknown option names return `400`.
Available in a batch.

A service artist also says which of the listener's library artists it is
(session feature `artistIdentity`). Artists are joined only on proof, never on
a name alone:

- `libraryArtist` is set when the service artist is proven to be a library
  artist: `{id,name,artwork,libraryId,by}`. `by` is `songs` (matched songs),
  `albums` (both have the same album) or `fix` (a person said so). Open the
  library artist's page with `libraryId`; it shows both.
- `couldBe` lists library artists of the same name that nothing ties it to and
  no one has ruled out: `[{id,name,artwork,libraryId,reason}]`. `reason` is a
  short sentence to show. A person decides with the artist link routes.

Both are absent for a library artist, for a name the library does not have, and
after a person answered "not the same". Reading with `include=albums` checks the
listed albums against the library's, so a shared album turns `couldBe` into
`libraryArtist` on that read.

```bash
curl -H "Authorization: Bearer $ALLSTARR_TOKEN" \
  "$BASE/allstarr/v2/artists/$ARTIST_ID?include=albums,tracks"
```

## Listener resources

### `GET /allstarr/v2/me/history`

Read qualified plays newest first. Query `limit` is 1–200, default 50; `before`
is the opaque `next` cursor from the previous page. Returns `{plays,next}`.
Each play has `{track,title,artist,album,durationMs,artwork,playedAt,isExternal,provider}`.
`track` is the current `V2Track`, or null when the song cannot be resolved.
The remaining fields preserve what was recorded, including unresolved imports.
Malformed paging returns `400`. Supports ETags and batch reads.

```bash
curl -H "Authorization: Bearer $ALLSTARR_TOKEN" \
  "$BASE/allstarr/v2/me/history?limit=50"
```

### `GET /allstarr/v2/me/history/rows`

Read the same plays as light rows (session feature `historyRows`), for lists that
read listener facts through `/tracks/facts`. Same `limit` and `before`; returns
`{plays,next}` where each play is `{trackId,aliases,libraryItemId,title,artists,
album,durationMs,artwork,playedAt,isExternal,provider}`. `trackId` is the id
`/history` gives the song's track, or null when the song cannot be resolved;
`libraryItemId` is set when the song is in the library. `artists` and `album` are
the song's refs (with `libraryId` or `aliases`, as on tracks); for an unresolved
song they carry the recorded names without ids. `title` is what the play recorded.
Rows carry no listener facts. Supports ETags and batch reads.

### `GET /allstarr/v2/me/history/imports`

Read the listener's latest 50 import previews and job status. No parameters.
Returns an array with import ID, revision, file name and size, expiration, state,
job status, errors, imported/duplicate/resolved/unresolved row counts and preview
counts. This read leaves imports unchanged. Supports ETags and batch reads.

```bash
curl -H "Authorization: Bearer $ALLSTARR_TOKEN" \
  "$BASE/allstarr/v2/me/history/imports"
```

### `GET /allstarr/v2/me/history/imports/recheck`

Check imported matches against the current matcher without changing them.
Optional query `examples=false` returns the counts with an empty `examples`
list, for apps that show only the counts. Returns `{songs,unchecked,doubtful,doubtfulPlays,examples}`.
Up to 200 examples contain `{track,recordingId,title,artist,album,matchedTitle,
matchedArtist,matchedAlbum,verdict,plays}`. `recordingId` uses the v2 track ID;
`track` is the matched `V2Track` or null when unavailable. Recorded and matched
names remain available for comparison. Supports ETags and batch reads.

```bash
curl -H "Authorization: Bearer $ALLSTARR_TOKEN" \
  "$BASE/allstarr/v2/me/history/imports/recheck"
```

### `GET /allstarr/v2/me/stats`

Read listening counts, coverage, timeline, hourly counts, streaks, genres and
ranked songs, artists and albums for this listener. Query `period` is `7d`,
`30d` (default), `year` or `all`. Alternatively use `year=1` through `9998`.
`timeZoneId` sets calendar boundaries, such as `America/New_York`. Invalid
periods, years or time zones return `400`; year and period cannot be combined.

`topSongs` entries are light rows `{trackId,aliases,libraryItemId,title,artist,artists,
album,playCount,artwork}`, as history rows are: `trackId` is the id a track read gives
the song (null when unavailable); `artist` and the album's name read as the plays
were counted; `artists` and the album's id are the refs pages open by. Listener
facts come from `/tracks/facts`. Artist entries have `{id,name,playCount,artwork}`
plus `libraryId` or `aliases` as on refs. Album entries have
`{title,artist,playCount,artwork}`.
Artwork objects contain a v2 `url`. Supports ETags and batch reads.

```bash
curl -G -H "Authorization: Bearer $ALLSTARR_TOKEN" \
  --data-urlencode 'period=30d' --data-urlencode 'timeZoneId=America/New_York' \
  "$BASE/allstarr/v2/me/stats"
```

### `GET /allstarr/v2/me/stats/art`

Load the artwork URL returned by stats or history with the listener's Bearer
header. Required query `artist`, optional `title` for a song or `album` for an
album, and optional `libraryArtistId` for a library artist. Names are at most
500 characters. Invalid artist IDs return `400`; hidden library artists return
`404`. Returns image bytes, or `204` when absent. Responses use private caching.
This file read cannot be batched.

```bash
curl -G -H "Authorization: Bearer $ALLSTARR_TOKEN" \
  --data-urlencode 'artist=Example artist' --data-urlencode 'title=Example song' \
  "$BASE/allstarr/v2/me/stats/art" --output artwork.image
```

### `GET /allstarr/v2/me/sound`

Read stored sound analysis for this listener. No parameters. Returns
`{songs,skippedSongs,librarySongs,traits,tempo,libraryTempo,at}`. Each trait has
`{name,difference,lean}`; scores compare finished songs with the library and
skips. Returns `404` until enough analysis exists. Supports ETags and batch reads.

```bash
curl -H "Authorization: Bearer $ALLSTARR_TOKEN" "$BASE/allstarr/v2/me/sound"
```

### `GET /allstarr/v2/me/taste`

Read `{lately,usually,latelyWeight,paused,useImportedHistory,nudges}` for this
listener. No parameters. Each taste layer has `tags` and `artists` with
`{name,strength}` entries. Nudges have `{kind,name,mode,expiresAt}`.
Supports ETags and batch reads.

```bash
curl -H "Authorization: Bearer $ALLSTARR_TOKEN" "$BASE/allstarr/v2/me/taste"
```

### `GET /allstarr/v2/me/preferences`

Read `{heartAction,libraries}` for this listener. No parameters. `heartAction`
defaults to `keep`. `libraries` is `{selected,available,revision}`: `revision` rises each time the choice is saved, from any app, and is 0 when it was never set; `available` lists the
music libraries this listener can open as `{id,name}`, and `selected` is the
chosen ids, or null for all of them. Mixes, Made for you and autoplay pick
library songs only from the chosen libraries. `libraries` is null when the
media server's libraries can't be read. Supports ETags and batch reads.

```bash
curl -H "Authorization: Bearer $ALLSTARR_TOKEN" "$BASE/allstarr/v2/me/preferences"
```

### `PATCH /allstarr/v2/me/preferences`

Set `heartAction` to `heart`, `keep` or `addToLibrary`, `libraries.selected` to
a list of `available` ids or null for all of them, or both. Fields left out
stay as they are; choosing every library is saved as null. Returns the full
preferences. A body with neither field, an invalid action, an empty list or an
unknown library returns `400`; a concurrent settings conflict returns `409`;
`503` when the libraries can't be read. Body limit: 1 KiB.

```bash
curl -X PATCH -H "Authorization: Bearer $ALLSTARR_TOKEN" \

```

## Search resources

### `GET /allstarr/v2/search`

Stream ranked search snapshots as `application/x-ndjson`. Required query `q`
is 1–200 characters after trimming. `limit` is 1–200, default 40. Optional
`types` is a comma-separated selection of `songs,albums,artists,playlists`,
default all. Invalid, repeated or empty type names return `400`.

Library results come from the music libraries the listener chose in "Your music
libraries" (`/me/preferences`), as mixes do; without a choice every library is
searched. Playlists and service results are not narrowed, and a service song
whose only library copy is in a library left out stays a service song.

Each line replaces the previous snapshot with `{revision,done,providers,top,
items,sections,late?}`. Sections use the requested type names. Each hit has
`{id,kind,score,source,sourceName,track?,album?,artist?,playlist?}`. Song hits
contain a `V2Track`; albums use the album summary shape above.

An artist summary is `{id,name,isExternal,artwork,alsoOn,namesakes}`. A library
artist that matched songs, a shared album or a person's answer tie to service artists is one hit
with `source:"allstarr"`; its `alsoOn` lists each part as
`{source,sourceName,id}`, the library artist first. Same-named artists from
other services are listed in the `alsoOn` of one service artist hit, its own
part first. `namesakes` lists library artists with the same name that a service
artist is not tied to, as `{id,name,libraryId}` references. A playlist summary is
`{id,name,curator,trackCount,isExternal,artwork}`; `curator` and `trackCount`
can be null. All summaries use native v2 IDs.

Album, artist and playlist summaries, and every `alsoOn` entry, also carry the
id the media-server routes open them by: `libraryId` for a library item, or
`aliases` with a service item's older `ext-` id. One of the two is present,
never both. The artist link routes take any of these spellings.

A song or album hit that stands for several copies has
`alsoOn:[{source,sourceName,id}]`, its own copy first, one per source. Songs
become one hit only on proof: the same saved recording or track id, the library
song Allstarr matched the copy to, or the same artist, title, version (live,
remix and the like) and explicitness, with both lengths known and within two
seconds, together with the same ISRC or the same album. A remaster joins only
the same remaster. The library copy leads. Copies without that proof stay
separate hits. Another service's copy of a listed album joins it when artist and
title match (ignoring "- Single" or "- EP") and year and track count agree where
both give them; library albums stay separate. Explicit and clean editions never
join; when both are listed their titles end in "(Explicit)" and "(Clean)".

Provider answers are accepted for 2.75 seconds and the last snapshot is
published within three seconds; `late` on the final snapshot names providers
that had not finished. The first snapshot waits for the preferred source and
another answer, or 400 ms; intermediate updates are at least 250 ms apart.
Disconnecting cancels the search. Search cannot be batched.

```bash
curl -N -G -H "Authorization: Bearer $ALLSTARR_TOKEN" \
  --data-urlencode 'q=Example artist' --data-urlencode 'types=songs,albums' \
  "$BASE/allstarr/v2/search"
```

### `GET /allstarr/v2/search/lyrics`

Search the stored lyrics index. Required query `q` is 2–200 characters after
trimming; optional `limit` is 1–50, default 20. Returns `{results,truncated}`.
Each result has `{track,line,highlights,score,source}` with a `V2Track`, matched
text, surrounding lines, optional timing and highlighted character ranges.
`score` is 1 when the line holds the whole phrase, 0.8 when it holds every word
in another order, and lower for some of the words, where everyday words such as
"you" or "the" count a fifth of other words and a line holding only those is
left out. A song whose title words are all in `q` gains 0.15, up to 0.95.
Results come in score order; a recording two services list appears once, as in
search, and a service song nobody has played yet still has its track (built from
its stored lyrics entry). Supports ETags and batch reads.

```bash
curl -G -H "Authorization: Bearer $ALLSTARR_TOKEN" \
  --data-urlencode 'q=words from a song' --data-urlencode 'limit=20' \
  "$BASE/allstarr/v2/search/lyrics"
```

### `GET /allstarr/v2/search/lyrics/services`

Ask lyrics services for songs with a lyric line. Required `q` is 2–200
characters after trimming; optional `limit` is 1–20, default 10. NetEase and
QQ Music are asked unless they are turned off in Sources; this read is slower
than `/search/lyrics`, so call both together and show library results first.
Optional `resolve=false` (session feature `lyricsSearchServicesResolve`)
answers as soon as the services do, usually within a second or two, with every
`track` null and `resolved:false`; the same request without it then returns
the same results in the same order with their tracks, reusing the services'
answer. Each result's `matchState` is `matched` (track set), `none` (looked up,
no playable song) or `pending` (not looked up yet, or cut off by the 5-second
limit for finding songs); ask again for pending results, which are looked up
again while finished ones are reused. A library copy is always looked up first.
Each service has 4 seconds. Answers are kept 30 minutes, or 2 minutes when a
service was unavailable or a result is pending. Optional header
`If-None-Match`. Available in a batch.

Returns `{results,providers,resolved}`. Each result is
`{title,artist,line:{text},highlights,provider,track,matchState}`: `highlights` are
`{start,length}` offsets in UTF-16 code units within `line.text`, as in
`/search/lyrics`; `provider` is `{id,name,iconUrl,glyphUrl}`; `track` is the
playable song matched by title and first artist, preferring a library copy from
the listener's chosen libraries, or null when none was found. The same song
found by several services appears once, and lines holding the whole phrase come
first. `providers` lists each service as `{id,name,state}` with state `ok`,
`unavailable` (failed or too slow) or `off`.

```bash
curl -H "Authorization: Bearer $ALLSTARR_TOKEN" \
  "$BASE/allstarr/v2/search/lyrics/services?q=something%20in%20the%20way%20that%20you%20walk"
```

## Batched reads

### `POST /allstarr/v2/batch`

Read several resources in one round trip. Endpoints are resources, not screens:
the client chooses the combination. Batch dispatches the same ordinary GET
readers and gives each item its own status. One failed read never fails the others.

Body: `{requests:[{id,path,ifNoneMatch?}]}` with 1–20 items. IDs must be unique,
1–64 characters. Each `path` is a full v2 path starting with `/allstarr/v2/`,
with its query, at most 8,192 characters. An optional `ifNoneMatch` carries the
stored ETag for that read. Reads run up to four at a time.

Only these GET reads are allowed, with the query options listed (each at most
once):

| Path | Query options |
| --- | --- |
| `/allstarr/v2/session` | none |
| `/allstarr/v2/tracks` | `ids`, `include`, `views` |
| `/allstarr/v2/tracks/facts` | `ids` |
| `/allstarr/v2/tracks/{id}` | `include`, `views` |
| `/allstarr/v2/tracks/{id}/lyrics` | `sourceId` |
| `/allstarr/v2/tracks/{id}/lyrics/sources` | `includeLyrics` |
| `/allstarr/v2/tracks/{id}/lyrics/translation` | `to` |
| `/allstarr/v2/tracks/{id}/match`, `/allstarr/v2/tracks/{id}/appearances` | none |
| `/allstarr/v2/tracks/{id}/autoplay` | `cursor`, `limit` |
| `/allstarr/v2/albums/{id}` | `include`, `views` |
| `/allstarr/v2/albums/{id}/similar` | `limit` |
| `/allstarr/v2/artists/{id}` | `include` |
| `/allstarr/v2/playback/{playbackId}` | none |
| `/allstarr/v2/mixes` | `timeZoneId` |
| `/allstarr/v2/mixes/{id}/tracks`, `/allstarr/v2/mixes/{id}/rows`, `/allstarr/v2/releases`, `/allstarr/v2/library/additions`, `/allstarr/v2/library/size`, `/allstarr/v2/models/karaoke` | none |
| `/allstarr/v2/me/history` | `limit`, `before` |
| `/allstarr/v2/me/history/rows` | `limit`, `before` |
| `/allstarr/v2/me/history/imports` | none |
| `/allstarr/v2/me/history/imports/recheck` | `examples` |
| `/allstarr/v2/me/stats` | `period`, `year`, `timeZoneId` |
| `/allstarr/v2/me/sound`, `/allstarr/v2/me/taste`, `/allstarr/v2/me/preferences` | none |
| `/allstarr/v2/search/lyrics` | `q`, `limit` |
| `/allstarr/v2/search/lyrics/services` | `q`, `limit`, `resolve` |

Everything else is excluded, including the search stream, artist links,
events, ping, playback resolution, stream access, covers, artwork, provider
icons, model downloads and every write. No method field or arbitrary URL is
accepted. Unsupported paths return per-item `404`; unknown or invalid options on
an allowed path return per-item `400`, except on the artist read, which returns
`404`.

Returns HTTP `200` with `{responses:{<id>:{status,body?,etag}}}`. Each successful
body is the same shape as the standalone route. Errors have `{code,error}`.
A matching `ifNoneMatch` produces per-item `304`, its ETag and no body.
An invalid outer envelope, including duplicate IDs, returns outer `400`.

```bash
curl -H "Authorization: Bearer $ALLSTARR_TOKEN" -H 'Content-Type: application/json' \
  --data "{\"requests\":[{\"id\":\"song\",\"path\":\"/allstarr/v2/tracks/$TRACK_ID?views=lyrics\"},{\"id\":\"album\",\"path\":\"/allstarr/v2/albums/$ALBUM_ID?include=tracks\"}]}" \
  "$BASE/allstarr/v2/batch"
```

## Playback resources

### `POST /allstarr/v2/playback/resolve`

Select a source and delivered format, then return a signed stream link valid for
12 hours. Body limit: 8 KiB.

| Body field | Values |
| --- | --- |
| `trackId` | Required track ID in any accepted spelling, at most 1,024 characters. |
| `tier` | Required: `original`, `lossless`, `high` (256 kbps), `normal` (160), `low` (96) or `lowest` (64). The household quality limit caps what services send; a file in the listener's own library is not capped by it. A listener's own quality limit applies to both. |
| `client` | Optional `{codecs:[string],maxSampleRate?,maxBitDepth?,channels?}`. At most 16 codecs; sample rate 8,000–384,000 Hz, depth 8–32, channels 1–8. |
| `purpose` | Optional `play`, `prefetch`, `download` or `cast`. Use `prefetch` for the next song; it can warm the external source in cache and starts the song's lyrics lookup. Use `download` for a copy to keep: a converted tier then comes as a file that can resume (below). |

Returns `{url,expiresAt,playbackId,cacheKey,source,delivered,transcoded,
contentLength,seek,trackGainDb,albumGainDb,provider,routeReason,loweredBy,serving}`.
`source` and `delivered` each have `{container,codec,bitrate,sampleRate,bitDepth,
isLossless}`. `provider` has `{id,name}`. `loweredBy` identifies a household or
listener quality limit, or is null. `serving`, when present, describes the caller's
active stream as `{codec,bitrate,bitDepth,sampleRate,source}`.

`cacheKey` hashes track, requested tier, delivered format and source identity;
it excludes the listener and signed token. Equal inputs produce the same key.
`seek=bytes` permits range resumes. `seek=none` does not. Live transcodes have
null `contentLength`, ignore Range and return a full `200` stream. A lossless
request can fall back; inspect `delivered` and `routeReason`.

**Downloads (session feature `resumableDownloads`).** With `purpose=download`, a tier
that needs converting is converted once into a file on the server and served from
that file. Resolve answers `transcoded=true` and `seek=bytes`; `contentLength` is the
copy's size once it exists and null before. The first `GET` waits for the conversion
(a few seconds) and then, like every later one, answers with `Content-Length`, an
`ETag`, `Accept-Ranges: bytes` and honours `Range`. Resume with `If-Range` and that
`ETag`: a copy that had to be made again answers `200` with the whole song. A new
link for the same song and tier finds the same copy, also when `cacheKey` has changed
because a service song's source moved into the server's cache; go by the `ETag`.
Copies leave one conversion free for listening, so with the default of two conversions
they are made one at a time: several downloads asked for at once wait their turn (each
`GET` simply takes longer), and one that has waited twenty seconds answers `503` with
`Retry-After`; ask again then. Copies are kept for a while and the ones read longest ago make room, never one
read in the last fifteen minutes. A tier that needs no conversion is the file itself,
as for playing.

Reading a track never opens audio. Resolve performs source inspection explicitly.
Prefetch can move audio into cache without invalidating the returned link.

```bash
curl -H "Authorization: Bearer $ALLSTARR_TOKEN" -H 'Content-Type: application/json' \
  --data "{\"trackId\":\"$TRACK_ID\",\"tier\":\"lossless\",\"purpose\":\"prefetch\",\"client\":{\"codecs\":[\"flac\",\"aac\"]}}" \
  "$BASE/allstarr/v2/playback/resolve"
```

### `GET /allstarr/v2/playback/{playbackId}`

Read `{playbackId,delivered,serving}` for the ID returned by resolve.
Both `delivered` and `serving` are null before the stream opens and after it
closes. While open, `delivered` describes the actual delivered format and
`serving` has the actual
`{source,codec,bitrate,sampleRate,bitDepth}`. `source` identifies the serving
service. A second resolve of the same track has its own playback status.

A stream opened through the media-server route `/Audio/{id}/stream` answers
with header `X-Allstarr-Playback-Request`; that id works here too (session
feature `playbackRequestStatus`) and returns `delivered` plus `provider`,
`cached`, `routeReason`, `trackId` (the id the stream was requested by) and
`startedAt`, kept after the stream closes, with `serving` null.

This read never opens audio, issues a link or prepares a source. No parameters.
Optional header `If-None-Match`. Another listener's or unknown playback returns
`404`; a malformed playback ID returns `400`. Status is held in memory for up
to 12 hours and is lost on restart or eviction. Available in a batch.

```bash
curl -H "Authorization: Bearer $ALLSTARR_TOKEN" \
  "$BASE/allstarr/v2/playback/$PLAYBACK_ID"
```

### `GET /allstarr/v2/stream/{token}`

Open the exact `url` returned by resolve. The signed path token authorizes the
track, tier and delivered format; a Jellyfin authorization header is unnecessary.
Do not build this URL yourself. Bad, expired or foreign tokens return `404`.

Returns audio with `200`, or `206` for a supported byte range. Stored files and
pass-through sources can support ranges when resolve advertises `seek=bytes`.
Live transcodes ignore Range. A download's converted copy supports ranges and can
answer `503` with `Retry-After` while it cannot be made yet (see resolve). The
source can move from provider to cache after prefetch. `STREAM_URL` below is the
returned URL.

```bash
curl -H 'Range: bytes=0-65535' "$STREAM_URL" --output sample.audio
```

### `HEAD /allstarr/v2/stream/{token}`

Inspect the signed media link's headers without returning an audio body.
Uses the same token and expiry rules. Success is `200`; an invalid link is `404`.
Length and range headers depend on the selected delivery.

```bash
curl -I "$STREAM_URL"
```

## Listener events

### `HEAD /allstarr/v2/ping`

Check reachability while the event stream is disconnected. Send the token in
the `Authorization` header, as Bearer or the MediaBrowser `Token=` form; other
credentials return `401`. No parameters. Returns `204` without a body.

```bash
curl -I -H "Authorization: Bearer $ALLSTARR_TOKEN" "$BASE/allstarr/v2/ping"
```

### `GET /allstarr/v2/events`

Open a listener-scoped server-sent event stream with an `Authorization` header (Bearer or the media server's own form).
Optional `Last-Event-ID` header takes precedence over the `lastEventId` query
cursor. It replays up to 1,000 retained events within ten minutes. Unknown or
expired cursors produce `resync` with `{}`: refetch state, then continue live.
Replay is held in memory. Comments ping every 25 seconds.

Returns `text/event-stream` frames with increasing `id`, `event` and JSON `data`.
Save the last received event ID. Reconnect with that cursor. The stream uses
the connection limits in the [API overview](README.md#limits-and-retries).

| Event | Data |
| --- | --- |
| `ready` | `{}`; sent on every connection after any replay, so the stream has a cursor before the first change. |
| `track.updated` | `{track:V2Track,changed?}`; `changed: ["loudness"]` when a service song's measured `trackGainDb` was just stored, to the listener who played it. |
| `lyrics.updated` | `{trackId,aliases,revision}`; `aliases` holds the library or service id the lyrics changed for. Reread the lyrics view. Also sent once when a lyrics versions list that came back with `pending` versions settles; reread the list. |
| `match.updated` | `{trackId,aliases,state}`; `aliases` are the track's other ids, as on V2Track. |
| `keep.updated` | `{trackId,aliases,state,progress?}` |
| `mix.updated` | `{mixId,playlistId,playlistLibraryId}`; `playlistLibraryId` is the media server's id for the mix's playlist, which `/Playlists` routes take. |
| `releases.updated` | `{count}` |
| `libraryAddition.updated` | `{row}`: `{id,itemId,unit,state,reason,libraryItemId?,requestedItemId?}`, where `itemId` is the id the addition was asked for. Sent at each step, with `title`, `artist`, `step`, `heldAt`, `stepsDone`, `stepsTotal`, `itemsDone` and `itemsTotal` as on the additions list. |
| `libraryRequest.updated` | `{row}` in the same shape, for a request waiting on an administrator. |
| `playback.updated` | `{trackId,aliases}`; `aliases` holds the id the playback was reported with. Sent to every app of the listener, not only the device playing; reread the playback status. |
| `preferences.updated` | `{field}`; `libraries` when the listener's music libraries changed anywhere. Reread `/me/preferences`. |
| `track.renamed` | `{old,new}`; reaches currently connected v2 listeners. |
| `resync` | `{}` |

```bash
curl -N -H "Authorization: Bearer $ALLSTARR_TOKEN" \
  -H "Last-Event-ID: $EVENT_ID" "$BASE/allstarr/v2/events"
```

## Artist links

These resources connect a library artist to service artist identities. Library
IDs can be native or v2 artist IDs; service IDs can be v2 or older `ext-` artist
IDs. The library side must resolve to an accessible Jellyfin `MusicArtist`.

Responses use `{links:[link],notSame:[link],candidates:[candidate]}`. Each link
has `{id,aliases,source,sourceName,by,scope,album?}`. `by` is `songs` for
matched-song evidence, `albums` when the service artist has an album the library
also holds under that artist (named in `album`), or `fix` for a person's choice.
Fix scope is `household` or `you`; computed evidence has null scope. A personal
choice wins over a household choice.

`candidates` (session feature `artistCandidates`) are service artists with the
library artist's name that nothing ties to it: no matched song, no shared album
and no answer. Each is `{id,aliases,source,sourceName,name,artwork,reason}`;
`reason` is a short sentence to show. They could be the same artist or a
namesake, so they stay separate until a person answers with PUT. An answer for
an artist covers it on every source of its service, and each service is listed
once.

A shared album must have a title of its own: an album named after the artist, or
a title many acts use such as "Greatest Hits", proves nothing.

### `GET /allstarr/v2/artists/{libraryArtistId}/links`

Read linked service artists, explicitly rejected identities and candidates. No
query parameters. Returns the artist-links response; inaccessible artists return
`404`. The first read of an artist asks the listener's services who answers to
the name and checks their albums against the library's; it waits up to three
seconds for that and finishes in the background, so read again when the list is
still empty. Later reads answer from what was saved.

```bash
curl -H "Authorization: Bearer $ALLSTARR_TOKEN" \
  "$BASE/allstarr/v2/artists/$LIBRARY_ARTIST_ID/links"
```

### `PUT /allstarr/v2/artists/{libraryArtistId}/links/{serviceArtistId}`

Set `{same:true}` for the same artist or `{same:false}` for a different act.
An administrator's answer covers the household; a listener's covers only them.
Search and artist pages use the new choice immediately. Returns the updated
artist-links response. Invalid service IDs return `400`.

```bash
curl -X PUT -H "Authorization: Bearer $ALLSTARR_TOKEN" -H 'Content-Type: application/json' \
  --data '{"same":true}' \
  "$BASE/allstarr/v2/artists/$LIBRARY_ARTIST_ID/links/$SERVICE_ARTIST_ID"
```

### `DELETE /allstarr/v2/artists/{libraryArtistId}/links/{serviceArtistId}`

Remove the caller's saved choice and let underlying evidence apply again.
No body or query parameters. Returns the updated artist-links response.
An administrator can remove the household choice using the same authority as
PUT. A listener cannot remove a household-only choice (`403`); they can save a
personal `same:false` choice instead.

```bash
curl -X DELETE -H "Authorization: Bearer $ALLSTARR_TOKEN" \
  "$BASE/allstarr/v2/artists/$LIBRARY_ARTIST_ID/links/$SERVICE_ARTIST_ID"
```

## Mixes

### `GET /allstarr/v2/mixes`

Read this listener's stored mixes. Optional `timeZoneId` selects the time zone
for dated mixes; an invalid zone returns `400`. Service feeds appear only when
added to apps. Reading mixes does not generate them. Supports batch and ETags.

Returns `{mixes:[{id,kind,name,description,state,itemCount,durationMs,updatedAt,
coverUrl,inApps,playlistId,playlistLibraryId?,artworkUrls,section,source,sourcePlaylistId,
appsUnavailableReason}]}`. `playlistLibraryId` is the media server's id for the
mix's playlist, which `/Playlists` routes take; `artworkUrls` are covers of the
mix's songs for tiling when it has no cover of its own.
`state` is `ready`, `empty`, `building` or `needs-listening`. `playlistId` is a
v2 playlist ID when published to apps, otherwise null. Open the returned
`coverUrl` with the listener's authorization header.

```bash
curl -H "Authorization: Bearer $ALLSTARR_TOKEN" \
  "$BASE/allstarr/v2/mixes?timeZoneId=UTC"
```

### `GET /allstarr/v2/mixes/{id}/tracks`

Read tracks in stored mix order. Accepts the returned v2 mix ID or its older
UUID. Returns `{id,updatedAt,tracks:[V2Track],missing:[id]}`. Tracks use the same
listener state and identity as other v2 track reads. Hidden mixes return `404`;
malformed IDs return `400`. Supports batch and ETags.

```bash
curl -H "Authorization: Bearer $ALLSTARR_TOKEN" \
  "$BASE/allstarr/v2/mixes/$MIX_ID/tracks"
```

### `GET /allstarr/v2/mixes/{id}/rows`

Read a mix's songs as light rows from the stored mix (session feature `mixRows`),
for lists that read listener facts through `/tracks/facts`. Returns
`{id,updatedAt,rows}` in stored order; each row is `{id,aliases,libraryItemId,title,
artists,album,durationMs,artwork,isExternal,provider}`. `id` is the same track ID
`/tracks` gives the song (its recording when known, the library copy of a service
song in the listener's library), so rows and full tracks match. Artists and album
are the stored names with the usual `libraryId` or `aliases`. Rows carry no
listener facts. Same errors as `/tracks`. Supports batch and ETags.

### `GET /allstarr/v2/mixes/{id}/cover`

Read a mix cover as JPEG or PNG. Use the returned cover URL, including its

returns `304` when unchanged. Partial collages retain a short private cache

```bash
curl -H "Authorization: Bearer $ALLSTARR_TOKEN" \
  "$BASE$MIX_COVER_URL" --output mix-cover.jpg
```

### `GET /allstarr/v2/releases/{id}/cover`

Read artwork for a release in this listener's inbox. Open its `coverUrl` with

```bash
curl -H "Authorization: Bearer $ALLSTARR_TOKEN" \

```

## Library additions

### `GET /allstarr/v2/library/size`

Read how much music the listener's own music libraries hold (session feature
`librarySize`): `{tracks,durationMs,bytes,sizedTracks}`. `bytes` is the size of the
files as they are, added up over the `sizedTracks` songs the media server gives a
size for. The size at a converted quality is `durationMs / 1000 * bitrate / 8`; for
one song, an album or a playlist, add up `durationMs` and `format.bitrate` from
their tracks the same way. Only the libraries chosen in the listener's preferences
count. The first read takes a few seconds on a large library; the answer is kept for
half an hour. No parameters. Supports batch and ETags.

```bash
curl -H "Authorization: Bearer $ALLSTARR_TOKEN" \
  "$BASE/allstarr/v2/library/size"
```

### `GET /allstarr/v2/library/additions`

Read only this listener's additions, newest first. Supports batch and ETags.
Returns an array of `{id,itemId,unit,state,reason,libraryItemId?,requestedItemId?,aliases}`.
`itemId` is the canonical v2 track ID; `requestedItemId` is the v2 spelling of the
track or album the addition was asked for. `aliases` lists the older ids of both
(such as `ext-…`), so an app holding those finds its addition. `libraryItemId`, when present, is the accessible native library
item created by the addition. States are `waitingForApproval`, `adding`, `done`,
`needsLook`, `declined` and `cancelled`.

With session feature `additionSteps` a row also says what it is and how far along, enough for a notice in an app
that did not start it. All of these are optional:

- `title`, `artist`: the song's, or the album's when `unit` is `album`.
- `step`: what is happening now, one of `fetching`, `checking`, `lyrics`, `tagging`, `loudness`, `placing`,
  `scanning`. `scanning` goes with state `done`: the file is in place and the media server has not shown it yet.
  When it has, `step` goes and `libraryItemId` appears. An addition from hours ago that the media server does not
  show (the item was moved or removed there since) is plain `done` without `step`.
- `stepsDone`, `stepsTotal`: for a progress bar. An album counts every song's steps.
- `itemsDone`, `itemsTotal`: for an addition of several songs, how many are in the library.
- `heldAt`: with `needsLook`, the step it stopped at, in the same names; absent when it stopped on an error.

`reason` is a sentence for the listener: what is being done, or with `needsLook` what was found and that nothing
was added (for several songs, how many were). A `needsLook` row with no `libraryItemId` added nothing.

```bash
curl -H "Authorization: Bearer $ALLSTARR_TOKEN" \
  "$BASE/allstarr/v2/library/additions"
```

### `POST /allstarr/v2/library/additions`

Body: `{itemId,unit}`, where `unit` is `song` or `album`. Accepts a v2 or older
track ID, or an album ID with `unit=album`. Uses the listener's library profile,
destination permissions and approval rules. Returns `202` with the addition.
Body limit: 8 KiB.

Optional `Idempotency-Key` is a nonempty retry key of at most 300 characters.
Replaying the same request within 24 hours returns `200` and the saved addition;
changing its item or unit returns `409`. Invalid input returns `400`; hidden
items or destinations return `404`.

```bash
curl -H "Authorization: Bearer $ALLSTARR_TOKEN" -H 'Content-Type: application/json' \
  -H "Idempotency-Key: $REQUEST_KEY" \
  --data "{\"itemId\":\"$TRACK_ID\",\"unit\":\"song\"}" \
  "$BASE/allstarr/v2/library/additions"
```

### `DELETE /allstarr/v2/library/additions/{id}`

Cancel this listener's pending request or running addition. No body. Returns
the updated addition. Files already added stay in the library. Another
listener's ID returns `404`; malformed UUIDs return `400`; an addition that
cannot be cancelled returns `409`.

```bash
curl -X DELETE -H "Authorization: Bearer $ALLSTARR_TOKEN" \
  "$BASE/allstarr/v2/library/additions/$ADDITION_ID"
```

## Reports

### `POST /allstarr/v2/reports`

Create a problem report. Body: `{kind,note,itemId?,playbackRequestId?}`. `kind`
is `wrong-song`, `wrong-lyrics`, `wont-play`, `bad-quality`, `wrong-info` or
`other`. `note` is 1–2,000 characters. `itemId` accepts a track ID in any
supported spelling. Returns `201` with `{id}`. Body limit: 16 KiB.

An optional playback request ID must belong to this listener and device;
unavailable or foreign context returns `404`. Without it, current playback on
the caller's device can supply context. The existing MediaBrowser authorization
header can carry `DeviceId` for this purpose. Invalid fields return `400`.

```bash
curl -H "Authorization: Bearer $ALLSTARR_TOKEN" -H 'Content-Type: application/json' \
  --data "{\"kind\":\"wrong-info\",\"note\":\"The title is incorrect\",\"itemId\":\"$TRACK_ID\"}" \
  "$BASE/allstarr/v2/reports"
```

## Karaoke models

Read the current validated model. Returns
`{version,sha256,sizeBytes,computeUnits,format,url,license}`. The versioned `url`
points to the v2 file resource. No available model returns `404`. Supports batch
and ETags.

```bash
curl -H "Authorization: Bearer $ALLSTARR_TOKEN" \

```

### `GET /allstarr/v2/models/karaoke/{version}/file`

Download a validated model with the authorization header. Returns
`application/octet-stream` with attachment filename, immutable private caching
and a SHA-256 ETag. Byte ranges return `206`; invalid ranges return `416`;

segments return `400`. Excluded from batch.

```bash
curl -H "Authorization: Bearer $ALLSTARR_TOKEN" \
  "$BASE$MODEL_URL" --output karaoke-model.aar
```

## Provider icons

### `GET /allstarr/v2/providers/{id}/icon`

Read installed provider artwork. Optional `variant=color|glyph` defaults to
`color`; optional `format=svg|png` selects an available format. Omitted format
uses the available default. SVG is served directly; raster assets are resized
to `size`, 16–256 pixels, default 96. Returns SVG or PNG with a private cache
policy and ETag. Supports `If-None-Match` and `304`. Unknown providers or absent
variants return `404`; invalid parameters return `400`. Excluded from batch.

V2 track providers and match candidates use this resource for `iconUrl` and
`glyphUrl`.

```bash
curl -H "Authorization: Bearer $ALLSTARR_TOKEN" \
  "$BASE/allstarr/v2/providers/$PROVIDER_ID/icon?variant=glyph&format=png&size=96" \
  --output provider-icon.png
```

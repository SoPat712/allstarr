# Client API v1

The v1 API adds personal Allstarr features to Jellyfin-compatible apps. Item IDs
use the Jellyfin surface: native library IDs and external `ext-...` IDs.
See the [API overview](README.md) for setup, listener restrictions, authentication
and errors, or the [v2 guide](v2.md) for the native API.

This guide covers the [checked-in v1 contract](../../apis/specifications/allstarr/client-v1.json).
Some routes require optional server features and may be unavailable in a given
build. Check capabilities before using optional features.

Examples assume the music listener is at `http://localhost:5274` and
`ALLSTARR_TOKEN` contains that listener's Jellyfin user token. Send credentials
in headers, including for images and downloads; never put a token in a URL.
Replace example IDs and revisions with values returned by your server.

JSON uses camelCase and strict numeric values. Durations named `durationMs` and
lyrics timestamps are milliseconds; bitrate is bits per second and sample rate
is Hz. Unknown values can be null, and some optional fields are omitted. A provider
object is `{id,name,iconUrl,glyphUrl}`; native library items use the provider from
`capabilities.library`, so use `isExternal` to distinguish service items.
Errors use `{code,error}` as described in the overview. Personal routes remain
personal for administrators. JSON reads generally disable caching; individual
image and download rules are listed below.

## Capabilities and search

### GET /allstarr/v1/capabilities

Read server support before opening optional screens. Returns
`{serverVersion,apiVersion,features,library,libraryAdditions,dashboard?}`.
`features` contains Boolean feature flags; `library` is the provider object for
the configured backend. `libraryAdditions` is
`{canAddDirectly,requiresApproval,defaultUnit}`, where the unit is `song` or
`album`. When a public dashboard address is configured, `dashboard` contains
`{url}`; it is omitted otherwise. The address opens normal browser sign-in.

```sh
curl -fsS -H "X-Emby-Token: $ALLSTARR_TOKEN" \
  http://localhost:5274/allstarr/v1/capabilities
```

### GET /allstarr/v1/search

Stream search results as newline-delimited JSON (`application/x-ndjson`). `q`
is required and must contain 1–200 characters after trimming. `limit` is 1–200;
its default is 20 per provider and kind. `types` is a comma-separated selection
of `Audio`, `MusicAlbum`, `MusicArtist`, and `Playlist`; omission selects all.
Omit `shape` for provider batches, or use `shape=ranked` for complete snapshots.
Other shapes return 400.

Default lines are `{provider,items:[...]}`, followed by `{done:true,late:[...]}`.
A provider can send more than one batch. Items have the normal Jellyfin search
shape plus lowercase numeric `score`, `source` and `sourceName`. Each batch is
sorted by score. Native library songs suppress matching service songs; native
rows are included only in ranked snapshots. Same-named library and service
albums or artists can remain separate results. Service playlists retain the
search route's `MusicAlbum` presentation.

Ranked lines replace the previous state:
`{revision,done,providers,top,items,sections,late?}`. Revisions increase from 1;
`providers` lists answered providers. `top` is one item or null, `items` is the
mixed ordered list, and `sections` contains requested arrays named `songs`,
`albums`, `artists`, and `playlists`. Each list has at most `limit` items across
providers; ranked requests default to 40. Missing arrays or section keys mean
empty. `late` is present on the final snapshot and identifies unfinished providers.

Render `top` followed by `items`, deduplicating by `Id` and preserving server
order. Native rows win ties; an exact-name artist can remain pinned as `top`.
Existing items change order only when a score leads by at least five points.
Linked library and service artists can become one item with `source:"allstarr"`,
`sourceName:"Allstarr"` and `alsoOn:[{source,sourceName,id}]`. Same-named service
artists can also combine this way; unlinked library namesakes may appear in
`namesakes:[{id,name}]`. Stable item IDs let clients update rows across snapshots.

Provider answers have a 2.75-second budget and publication has a three-second
budget. The first ranked snapshot waits for the preferred provider and another
answer, or 400 ms; intermediate snapshots are at least 250 ms apart. Disconnecting
cancels that request's search work. Both shapes use `Cache-Control: no-store,
no-transform` and disable response buffering.

```sh
curl -fsS -N -G -H "X-Emby-Token: $ALLSTARR_TOKEN" \
  --data-urlencode 'q=Example Artist' --data-urlencode 'shape=ranked' \
  --data-urlencode 'types=Audio,MusicAlbum,MusicArtist,Playlist' \
  http://localhost:5274/allstarr/v1/search
```

### GET /allstarr/v1/search/lyrics

Search lyrics already stored by Allstarr. Required `q` is 2–200 characters after
trimming; `limit` is 1–50, default 20. Returns `{results,truncated}`, with one
best line per song ordered by score. Each result is
`{itemId,title,artist,album,albumId,isExternal,line,highlights,score,source}`.
`line` is `{text,startMs,endMs,before,after,synced}`, `highlights` contains
`{start,length}` UTF-16 offsets within `line.text`, `score` is 0–1, and `source`
is `{id,name}`. Unknown timing, album IDs and neighbouring lines are null.
`synced` is true when a playback start time is known, including zero.

Matching ignores case, accents, punctuation and whitespace; phrases can span
two lines. Effective lyrics choices and listener visibility apply. This read
makes no lyrics or metadata requests to music services. No hits returns
`{results:[],truncated:false}`; invalid input returns 400.

```sh
curl -fsS -G -H "X-Emby-Token: $ALLSTARR_TOKEN" \
  --data-urlencode 'q=two moons' --data-urlencode 'limit=20' \
  http://localhost:5274/allstarr/v1/search/lyrics
```

## Item details, lyrics and matches

### POST /allstarr/v1/items/details

Read stored details for 1–100 IDs using `{"ids":[...]}`. Returns `{items,missing}`;
unknown and hidden IDs both appear in `missing`. Items preserve requested ID
spelling and order, including repeats. Each item contains
`{id,isExternal,canonicalRecordingId,isrc,provider,audio,explicit,saved,keep,match,lyrics}`:

| Field | Shape or meaning |
| --- | --- |
| `audio` | Measured `{codec,bitDepth,sampleRate,bitrate}`, or null. |
| `explicit` | Boolean or null when unknown. |
| `saved` | Whether this listener has hearted the item. |
| `keep` | `{state,progress}`; state is `none`, `inProgress`, `kept`, or `failed`; progress is 0–1 or null. |
| `match` | `{state,confidence,authority}` or null; authority is `automatic`, `household`, or `personal`. |
| `lyrics` | Stored `{available,format,source}`; format is `word`, `line`, `plain`, or null. |

Song rows also include personal `playCount` and optional `lastPlayedAt`; unplayed
songs have count zero. Album and artist rows omit those fields. Counts include
linked recording history and imports. Details read stored lyrics availability;
they do not fetch lyrics from providers.

```sh
curl -fsS -X POST -H "X-Emby-Token: $ALLSTARR_TOKEN" \
  -H 'Content-Type: application/json' \
  --data '{"ids":["library-item-id","ext-deezer-song-123"]}' \
  http://localhost:5274/allstarr/v1/items/details
```

### GET /allstarr/v1/items/{itemId}/lyrics

Read effective rich lyrics for a native or external song. Optional `sourceId`
previews one version without pinning it or changing effective lyrics. The result
is `{source:{id,name},format,lines}`. Format is `word`, `line`, or `plain`; each
line is `{startMs,endMs,text,part,words,voice?,singer?}` and each word is
`{startMs,endMs,text}`. Line timing has empty `words`; plain text also has null
line times. Background vocals retain separate timing.

The effective personal or household pin takes precedence, then automatic source
selection applies. Reads can return known lyrics while concurrent provider work
continues to fill caches; a temporary 404 can become available on a later read.
Unknown, hidden or lyricless items and unavailable preview versions return 404.

```sh
curl -fsS -H "X-Emby-Token: $ALLSTARR_TOKEN" \
  http://localhost:5274/allstarr/v1/items/ext-deezer-song-123/lyrics
```

### GET /allstarr/v1/items/{itemId}/lyrics/sources

Review versions for a song. `includeLyrics=true` includes the full rich lyrics
in each ready candidate; the default is false. Returns `{sources,chosen,revision}`.
Each source has
`{sourceId,providerId,providerName,title,artist,album,durationMs,format,preview,state,score,rank,reasons,lyrics?}`.
`state` is `ready` or `pending`; pending rows have null format, preview, score,
rank and reasons. Previews contain up to four lines and 1,000 characters. Ready
sources are ranked best first, with scores from 0–1 and ranks starting at 1.

`chosen` is `{sourceId,layer}` or null, with layer `personal`, `household`, or
`automatic`. `revision` is `{personal,household}`; each value is null or
`{id,revision}` with a numeric revision. Keep this complete object for writes.
Source IDs are opaque and may include a provider version suffix. Background
lookups can turn pending candidates into ready ones on subsequent reads.

```sh
curl -fsS -H "X-Emby-Token: $ALLSTARR_TOKEN" \
  'http://localhost:5274/allstarr/v1/items/ext-deezer-song-123/lyrics/sources?includeLyrics=true'
```

### PUT /allstarr/v1/items/{itemId}/lyrics/source

Pin a source for this listener using `{sourceId,expectedRevision}`. Copy the
complete revision object from the latest sources response; the null stamps below
are an example of an item without saved pins. Returns `{chosen,revision}` in the
same shapes as source review. A stale revision or unavailable source returns
409. Writes require a known recording; an unresolved item returns 404. Personal
pins override household and automatic selection.

```sh
curl -fsS -X PUT -H "X-Emby-Token: $ALLSTARR_TOKEN" \
  -H 'Content-Type: application/json' \
  --data '{"sourceId":"lrclib:123","expectedRevision":{"personal":null,"household":null}}' \
  http://localhost:5274/allstarr/v1/items/ext-deezer-song-123/lyrics/source
```

### POST /allstarr/v1/items/{itemId}/lyrics/source/clear

Clear this listener's pin using `{expectedRevision}` copied from the latest
sources or write response. Returns `{chosen,revision}`. Selection falls back to
the household pin, then automatic rules. A stale revision returns 409; a missing
known recording returns 404. The example revision must be replaced before use.

```sh
curl -fsS -X POST -H "X-Emby-Token: $ALLSTARR_TOKEN" \
  -H 'Content-Type: application/json' \
  --data '{"expectedRevision":{"personal":{"id":"11111111-1111-4111-8111-111111111111","revision":1},"household":null}}' \
  http://localhost:5274/allstarr/v1/items/ext-deezer-song-123/lyrics/source/clear
```

### GET /allstarr/v1/items/{itemId}/match

Read the effective match and available candidates. Returns
`{state,confidence,authority,current,candidates,revision}`. `authority` is
`automatic`, `household`, or `personal`; `current` is one candidate or null.
Each candidate is
`{candidateId,title,artist,album,durationMs,isrc,provider,isExternal,confidence,reasons}`.
Unknown metadata is null. Candidates use opaque IDs and saved evidence in
`reasons`. `revision` is an opaque string to copy unchanged into writes.

Native and canonical IDs require a known recording linked to an accessible
stored source snapshot; provider song IDs use the listener's stored snapshot.
Missing or hidden snapshots return 404. Personal choices take precedence over
household and automatic matching. All match writes below affect only this
listener and return the complete updated match shape.

```sh
curl -fsS -H "X-Emby-Token: $ALLSTARR_TOKEN" \
  http://localhost:5274/allstarr/v1/items/ext-deezer-song-123/match
```

### PUT /allstarr/v1/items/{itemId}/match

Choose a returned candidate using `{candidateId,expectedRevision}`. Returns the
updated match object described above. A stale revision returns 409; an
unavailable candidate returns 400. Refetch after any successful write.

```sh
curl -fsS -X PUT -H "X-Emby-Token: $ALLSTARR_TOKEN" \
  -H 'Content-Type: application/json' \
  --data '{"candidateId":"candidate-id","expectedRevision":"opaque-revision"}' \
  http://localhost:5274/allstarr/v1/items/ext-deezer-song-123/match
```

### DELETE /allstarr/v1/items/{itemId}/match

Clear this listener's choice or rejection. Required query parameter
`expectedRevision` is the latest opaque match revision. Returns the updated
match object, falling back to household or automatic matching; stale revisions
return 409.

```sh
curl -fsS -X DELETE -H "X-Emby-Token: $ALLSTARR_TOKEN" \
  'http://localhost:5274/allstarr/v1/items/ext-deezer-song-123/match?expectedRevision=opaque-revision'
```

### POST /allstarr/v1/items/{itemId}/match/reject

Reject the match for this listener using `{expectedRevision}`. Returns the
updated match object with no current candidate. A stale revision returns 409.

```sh
curl -fsS -X POST -H "X-Emby-Token: $ALLSTARR_TOKEN" \
  -H 'Content-Type: application/json' --data '{"expectedRevision":"opaque-revision"}' \
  http://localhost:5274/allstarr/v1/items/ext-deezer-song-123/match/reject
```

### GET /allstarr/v1/items/{itemId}/appearances

Find a song's or album's appearances in this listener's mixes and synced service
playlists. Returns `{itemId,songCount,appearances}`; each appearance is
`{kind,id,title,subtitle,coverUrl,matchedSongCount,playlistId}`. Kind is `mix` or
`playlist`; a mix's `playlistId` is null until published in apps. Results sort by
matched song count, then mixes before playlists. Native IDs, service song and
album IDs, and albums built from saved playlist songs are accepted. Other types
return 400; unknown or hidden items return 404. Ordinary playlists created in
Jellyfin are excluded.

```sh
curl -fsS -H "X-Emby-Token: $ALLSTARR_TOKEN" \
  http://localhost:5274/allstarr/v1/items/ext-deezer-album-123/appearances
```

### GET /allstarr/v1/items/{itemId}/similar

Read related albums for an album ID. `limit` defaults to 12 and is clamped to
1–24. Returns
`{itemId,basedOn,albums}`; `basedOn` identifies the source of related artists or
is null. Each album is
`{id,title,artist,artistId,year,songCount,coverUrl,source,isExternal,provider}`;
unknown metadata is null and `source` is `library` or a service ID. The server
prefers the listener's most-played library album by each related artist,
otherwise a recent service album, preferring albums over singles and compilations.
Results are cached per listener
for two minutes and recheck listening policy. Non-albums return 400.

```sh
curl -fsS -H "X-Emby-Token: $ALLSTARR_TOKEN" \
  'http://localhost:5274/allstarr/v1/items/ext-deezer-album-123/similar?limit=12'
```

## Playback and reports

Playback requests require the same device identity used for the stream and
playback reports. Supply `DeviceId` in the MediaBrowser authorization header, as
in these examples, or use the `deviceId` query parameter. Credentials stay in
headers. Playback facts have shape
`{provider,accountScope,cached,delivered,routeReason,itemId,startedAt}`.
`accountScope` is `personal`, `shared`, or null. `delivered` is
`{format,codec,bitDepth,sampleRate,bitrate}` or null and describes the actual
output, including conversion. Account names and IDs are excluded.

### GET /allstarr/v1/playback/{requestId}

Read a provider stream's facts using the `X-Allstarr-Playback-Request` response
header value as `requestId`. Returns the playback shape above. Malformed,
expired, hidden, another listener's or another device's IDs return 404. A request
without a device identity also returns 404.

```sh
curl -fsS -H "Authorization: MediaBrowser Token=\"$ALLSTARR_TOKEN\", DeviceId=\"example-device\"" \
  http://localhost:5274/allstarr/v1/playback/11111111-1111-4111-8111-111111111111
```

### GET /allstarr/v1/playback/current

Read active playback on this device, including native library tracks. Returns
the playback shape above, using reports from the last five minutes. Missing
device identity, stopped or inactive playback returns 404. Native playback uses
`capabilities.library`, null account scope and route reason `native-local-library`.

```sh
curl -fsS -H "Authorization: MediaBrowser Token=\"$ALLSTARR_TOKEN\", DeviceId=\"example-device\"" \
  http://localhost:5274/allstarr/v1/playback/current
```

### POST /allstarr/v1/reports

Create a personal problem report. Body:
`{kind,note,itemId?,playbackRequestId?}`. Kind is `wrong-song`, `wrong-lyrics`,
`wont-play`, `bad-quality`, `wrong-info`, or `other`; trimmed notes contain
1–2,000 characters. The request-size limit is 16 KiB, and unknown body fields
are rejected. Returns `201 {id}`.

An explicit playback request must belong to this listener and device and agree
with `itemId` if supplied. Hyphenated and 32-hex GUID forms are accepted.
Unknown, expired or foreign context returns 404. Without an explicit request,
recent playback on the same device can supply context.

```sh
curl -fsS -X POST \
  -H "Authorization: MediaBrowser Token=\"$ALLSTARR_TOKEN\", DeviceId=\"example-device\"" \
  -H 'Content-Type: application/json' \
  --data '{"kind":"wrong-song","note":"The live version plays instead.","itemId":"ext-deezer-song-123"}' \
  http://localhost:5274/allstarr/v1/reports
```

## Mixes, releases and follows

### GET /allstarr/v1/mixes

List mixes in the listener's For you order. Optional `timeZoneId` uses the saved
preference when omitted. Returns `{mixes:[...]}`. Each mix is
`{mixId,kind,name,description,state,itemCount,durationMs,updatedAt,coverUrl,inApps,playlistId,artworkUrls,section,source,sourcePlaylistId,appsUnavailableReason}`.
State is `ready`, `empty`, `building`, or `needs-listening`. Sections include
`madeForYou`, `moods`, `custom`, and `yourServices`. Service feeds use
`kind:"external"` and a service `source`; only feeds added to apps are listed.
Other mixes have null source fields. Optional artwork and availability details
can be null.

Reads do not generate listening-based mixes. Counts and duration reflect songs
visible under this listener's access and listening policy. Unopened service
feeds can have a source-reported count and zero duration. `playlistId` is null
when unpublished; `inApps` reflects actual publication availability.

```sh
curl -fsS -G -H "X-Emby-Token: $ALLSTARR_TOKEN" \
  --data-urlencode 'timeZoneId=America/New_York' \
  http://localhost:5274/allstarr/v1/mixes
```

### GET /allstarr/v1/mixes/{mixId}/items

Read one mix's songs in mix order. `mixId` is a GUID from the list. Returns
`{mixId,updatedAt,items}` with each item shaped as
`{itemId,title,artist,album,albumId,artworkUrl,artistId,durationMs,isExternal,provider,reason}`.
Unknown relationships, artwork and durations can be null. Songs outside the
listener's current view are omitted. Unknown mixes and service feeds not added
to apps return 404.

```sh
curl -fsS -H "X-Emby-Token: $ALLSTARR_TOKEN" \
  http://localhost:5274/allstarr/v1/mixes/11111111-1111-4111-8111-111111111111/items
```

### GET /allstarr/v1/mixes/{mixId}/cover

Download a mix's JPEG collage or PNG fallback. `mixId` is a GUID; optional `v`
is the version from `coverUrl`. A complete cover requested at its current version
can be cached privately for a year with `immutable`; incomplete artwork uses a
short cache. Other responses require revalidation and support ETag/304.
Unknown, hidden or unadded service feeds return 404, including conditional reads.
Use the returned `coverUrl` unchanged when possible.

```sh
curl -fsS -H "X-Emby-Token: $ALLSTARR_TOKEN" \
  http://localhost:5274/allstarr/v1/mixes/11111111-1111-4111-8111-111111111111/cover \
  -o mix-cover.jpg
```

### GET /allstarr/v1/releases

Read the stored New releases inbox and followed artists. Returns
`{releases,followedArtists}`. Each release is
`{releaseId,title,kind,releaseDate,artist,albumId,coverUrl}`; artist objects are
`{artistId,name,imageUrl}` with nullable IDs and pictures. Dates preserve the
source's precision. Dismissed and excluded entries are omitted. The route does
not poll providers for new releases; reading it can reconcile existing artist
favourites with follows.

```sh
curl -fsS -H "X-Emby-Token: $ALLSTARR_TOKEN" \
  http://localhost:5274/allstarr/v1/releases
```

### GET /allstarr/v1/releases/{releaseId}/cover

Download artwork for an entry in this listener's inbox. `releaseId` comes from
the release list. Returns image bytes with private seven-day caching and
ETag/304 support, or 204 when no artwork is available. Missing artwork normally
uses a one-hour cache; a timed-out lookup uses one minute. An entry outside the
listener's inbox returns 404.

```sh
curl -fsS -H "X-Emby-Token: $ALLSTARR_TOKEN" \
  http://localhost:5274/allstarr/v1/releases/release-id/cover -o release-cover.jpg
```

### PUT /allstarr/v1/artists/{artistId}/follow

Follow a service or visible native library artist; no body is required. Native
artists pass an authenticated library lookup, then use stored identity and
library songs or albums to resolve a service artist when possible. A native
artist can remain followed without a service match. Returns
`{followed:true,artist:{artistId,name,imageUrl}}`; a native ID can use Jellyfin's
canonical spelling. Repeating the operation is safe. Unknown or hidden artists
return 404 `artist_not_found`.

```sh
curl -fsS -X PUT -H "X-Emby-Token: $ALLSTARR_TOKEN" \
  http://localhost:5274/allstarr/v1/artists/ext-deezer-artist-123/follow
```

### DELETE /allstarr/v1/artists/{artistId}/follow

Unfollow an artist using the same IDs and access rules as follow; no body is
required. Returns `{followed:false,artist:{artistId,name,imageUrl}}`. Repeating
the operation is safe; an unresolvable artist returns 404 `artist_not_found`.

```sh
curl -fsS -X DELETE -H "X-Emby-Token: $ALLSTARR_TOKEN" \
  http://localhost:5274/allstarr/v1/artists/ext-deezer-artist-123/follow
```

## Library additions and preferences

An addition receipt has
`{id,itemId,requestedItemId?,unit,state,reason,libraryItemId?}`. `itemId` is the
representative recording's canonical `ext-allstarr-song-...` ID;
`requestedItemId` preserves the submitted ID. Unit is `song` or `album`. States
are `adding`, `waitingForApproval`, `needsLook`, `done`, `declined`, and
`cancelled`. `reason` is display text. `done` means files were placed and a
backend scan was queued; `libraryItemId` appears after the native song is matched,
including for an album addition. These routes use `private, no-store`.

### GET /allstarr/v1/library/additions

Read this listener's additions and requests as an array of addition receipts.
An approved request retains its request ID; a matching linked run is not listed
again. Older receipts can omit `requestedItemId`.

```sh
curl -fsS -H "X-Emby-Token: $ALLSTARR_TOKEN" \
  http://localhost:5274/allstarr/v1/library/additions
```

### POST /allstarr/v1/library/additions

Add music or request household approval using `{itemId,unit}`. `itemId` must be
nonblank and no longer than 500 characters. A song with unit `song` adds just
that song; unit `album` adds its release. External album IDs require unit
`album`. Existing library setup, quality and approval rules apply. Returns
202 with an addition receipt.

Optional `Idempotency-Key` is a nonblank header of at most 300 characters, scoped
to this listener for 24 hours. Reusing it with the same item and unit returns
200 with the current receipt; changing either returns 409.

```sh
curl -fsS -X POST -H "X-Emby-Token: $ALLSTARR_TOKEN" \
  -H 'Content-Type: application/json' -H 'Idempotency-Key: example-addition-1' \
  --data '{"itemId":"ext-deezer-song-123","unit":"song"}' \
  http://localhost:5274/allstarr/v1/library/additions
```

### POST /allstarr/v1/library/additions/{id}/cancel

Cancel a pending request or this listener's own addition. `id` is the receipt's
GUID; no body is required. Returns the updated addition receipt. Files already
placed remain in the library. Cancelling another listener's shared run returns
409; foreign receipt IDs return 404.

```sh
curl -fsS -X POST -H "X-Emby-Token: $ALLSTARR_TOKEN" \
  http://localhost:5274/allstarr/v1/library/additions/11111111-1111-4111-8111-111111111111/cancel
```

### GET /allstarr/v1/preferences

Read `{heartAction}` for this listener. The default is `keep`. Values are
`heart` (heart only), `keep` (also retain a copy), and `addToLibrary` (heart and
use the same library-addition approval path).

```sh
curl -fsS -H "X-Emby-Token: $ALLSTARR_TOKEN" \
  http://localhost:5274/allstarr/v1/preferences
```

### PATCH /allstarr/v1/preferences

Save `{heartAction}` with one of the values above. Returns the saved
`{heartAction}`. It affects future hearts; existing copies and additions remain.
Invalid values return 400 and a concurrent settings change can return 409.

```sh
curl -fsS -X PATCH -H "X-Emby-Token: $ALLSTARR_TOKEN" \
  -H 'Content-Type: application/json' --data '{"heartAction":"addToLibrary"}' \
  http://localhost:5274/allstarr/v1/preferences
```

## Listening history and profiles

All `/me` routes are scoped to this listener. JSON responses use
`Cache-Control: private, no-store`. Availability depends on server features.

### GET /allstarr/v1/me/history

Read durable listening history. `limit` is 1–200, default 50; optional `before`
is the opaque `next` cursor from the previous response. Returns `{plays,next?}`;
`next` is omitted at the end. Plays are newest first with stable ordering for
equal timestamps. Each play is
`{itemId,title,artist,album,durationMs,artworkUrl,playedAt,isExternal,provider}`.
Unknown metadata is null except title and artist, which use empty text. Imported
plays without a playable item have null `itemId`. Artwork requires the same
listener token. Completed plays and stopped plays reaching 30 seconds count;
imports are included regardless of taste settings. Invalid paging returns 400.

```sh
curl -fsS -H "X-Emby-Token: $ALLSTARR_TOKEN" \
  'http://localhost:5274/allstarr/v1/me/history?limit=50'
```

### GET /allstarr/v1/me/history/imports

Read up to 50 recent imports as an array of import-status objects:
`{importId,revision,displayFileName,sizeBytes,expiresAt,state,jobId,jobState,lastErrorCode,lastErrorMessage,importedRows,duplicateRows,resolvedRows,unresolvedRows,preview}`.
Job and error fields can be null. `preview` contains format, file and music row
counts, completed/partial/skipped counts, duplicates, resolution totals,
source-user counts, time bounds and reason counts. This is a read-only status
surface; the full field definitions are in the checked-in contract.

```sh
curl -fsS -H "X-Emby-Token: $ALLSTARR_TOKEN" \
  http://localhost:5274/allstarr/v1/me/history/imports
```

### GET /allstarr/v1/me/history/imports/recheck

Read stored match-quality information for imported history. Returns
`{songs,unchecked,doubtful,doubtfulPlays,examples}`. Each example is
`{recordingId,title,artist,album,matchedTitle,matchedArtist,matchedAlbum,verdict,plays}`;
unknown artist and album metadata is null. This read does not start an import or
change saved matches.

```sh
curl -fsS -H "X-Emby-Token: $ALLSTARR_TOKEN" \
  http://localhost:5274/allstarr/v1/me/history/imports/recheck
```

### GET /allstarr/v1/me/stats

Read personal listening totals and rankings. Use `period=7d|30d|year|all`
(default `30d`) or `year=1` through `9998`, never both. Optional `timeZoneId` is a
system ID such as `America/New_York`; omission uses the server's time zone.
Invalid windows or zones return 400. Calendar windows include their start and
exclude their end.

The response includes `period:{from,to,timeZoneId}`, `playCount`, `activeDays`,
`importedCount`, `observedSince`, `estimatedTimeFromSongLengthsMilliseconds`,
`coverage:{unknownSongIdentityCount,unknownDurationCount}`, `topSongs`,
`topArtists`, `topAlbums`, `shortPlayCount`, `firstPlayAt`, `uniqueSongs`,
`uniqueArtists`, `timelineUnit`, `timeline`, `byHour`, `biggestDay`,
`longestStreakDays`, `topGenres`, `newArtistCount`, and `newArtists`.
Song rows are `{title,artist,album,playCount,artworkUrl}`, artist rows are
`{name,playCount,artworkUrl,id?}`, and album rows are
`{title,artist,playCount,artworkUrl}`. Timeline points are `{key,plays}`; genre
rows are `{genre,plays}`. Use supplied artwork URLs, including any
`libraryArtistId` query parameter.

```sh
curl -fsS -G -H "X-Emby-Token: $ALLSTARR_TOKEN" \
  --data-urlencode 'period=30d' --data-urlencode 'timeZoneId=America/New_York' \
  http://localhost:5274/allstarr/v1/me/stats
```

### GET /allstarr/v1/me/stats/art

Download personal stats or history artwork. `artist` is required and nonblank;
add `title` for a song or `album` for an album. Omitting both requests an artist
photo. Optional `libraryArtistId` comes from a returned artwork URL. Returns
image bytes with private seven-day caching, or 204 with private one-hour caching
when absent. Authenticate image requests with the listener token.

```sh
curl -fsS -G -H "X-Emby-Token: $ALLSTARR_TOKEN" \
  --data-urlencode 'artist=Example Artist' --data-urlencode 'album=Example Album' \
  http://localhost:5274/allstarr/v1/me/stats/art -o stats-art.jpg
```

### GET /allstarr/v1/me/taste

Read `{lately,usually,latelyWeight,paused,useImportedHistory,nudges}`. Each layer
has `tags` and `artists` arrays of `{name,strength}`, with strengths from 0–100.
Nudges are `{kind,name,mode,expiresAt}`; null expiry means ongoing. The last
computed profile can return while changed inputs refresh in the background.
Current saved nudges and learning settings are included immediately.

```sh
curl -fsS -H "X-Emby-Token: $ALLSTARR_TOKEN" \
  http://localhost:5274/allstarr/v1/me/taste
```

### GET /allstarr/v1/me/sound

Read `{songs,skippedSongs,librarySongs,traits,tempo,libraryTempo,at}`. Traits are
`{name,difference,lean}`: difference compares finished songs with the library;
lean compares finished and skipped songs. Unknown lean or tempo is null.
Insufficient listening history or unavailable analysis returns 404; clients
should show an empty state until a profile is available.

```sh
curl -fsS -H "X-Emby-Token: $ALLSTARR_TOKEN" \
  http://localhost:5274/allstarr/v1/me/sound
```

## Images and downloads

### GET /allstarr/v1/providers/{providerId}/icon

Download a provider icon. `variant` is `color` (default) or `glyph`; optional
`format` is `svg` or `png`, defaulting to an available SVG and otherwise PNG.
`size` is 16–256 pixels, default 96. Returns SVG or PNG bytes with private
one-day caching and ETag/304 support. Missing providers, icons or formats return
404; invalid query values return 400. A dashboard cookie does not replace the
listener token.

```sh
curl -fsS -H "X-Emby-Token: $ALLSTARR_TOKEN" \
  'http://localhost:5274/allstarr/v1/providers/deezer/icon?variant=glyph&format=png&size=96' \
  -o provider-icon.png
```

### GET /allstarr/v1/models/karaoke

Read metadata for the newest valid on-device karaoke model. Returns
`{version,sha256,sizeBytes,computeUnits,format,url,license}`; `url` points to its
file route. No valid model returns 404. Check `features.karaokeModel` first.

```sh
curl -fsS -H "X-Emby-Token: $ALLSTARR_TOKEN" \
  http://localhost:5274/allstarr/v1/models/karaoke
```

### GET /allstarr/v1/models/karaoke/{version}/file

Download the model version returned by metadata. Returns
`application/octet-stream` with attachment disposition, a SHA-256 ETag, and
private immutable caching for one year. Range requests can return 206; an
unsatisfiable range returns 416. The same path supports HEAD. Invalid or unknown
versions return 404. Model files stream from disk.

```sh
curl -fsS -H "X-Emby-Token: $ALLSTARR_TOKEN" \
  http://localhost:5274/allstarr/v1/models/karaoke/model-version/file -o karaoke-model.bin
```

## Jellyfin compatibility

Send `X-Allstarr-Title-Markers: none` on a music request to suppress `[A]` and
`[E]` title markers for that request. This also applies to normal Jellyfin routes
and does not change saved preferences. Browser clients can send the extra
`X-Allstarr-*` and `Idempotency-Key` headers; CORS exposes
`X-Allstarr-Playback-Request`.

Native Jellyfin search accepts `allstarrScope=library` to search only the backend
library. Without that parameter, the existing merged search remains available.
Jellyfin album Similar routes return the same recommendations as the v1 similar
route, with `AllstarrSource`, `AllstarrProvider` and `AllstarrBasedOn` metadata.

Synced playlists can carry `AllstarrPlaylistKind` (`Yours`, `Feed`, `Followed`, or
`Mix`). Published mixes also carry `AllstarrMixKind`, `AllstarrMixSection`,
`AllstarrMixState`, `AllstarrMixSource` and content-update metadata; their songs
can carry `AllstarrReason`. These stay ordinary Jellyfin playlists for playback.
Favouriting or unfavouriting an artist through Jellyfin also follows or unfollows
that artist for New releases.
